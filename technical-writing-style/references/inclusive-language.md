# Inclusive language

Software reaches people worldwide. Content that excludes people is a defect.

Tables show each rule as a before and an after. They illustrate the rule. They are not phrases to find and replace.

**Limit.** A term that's part of a command, a setting, an API, or a quoted UI label stays as written. Flag it if it should change in the product.

## Pronouns in generic references

Don't use _he, him, his, she, her,_ or _hers_ for a generic person. In order of preference: rewrite to _you,_ rewrite to a plural, use _the_ or _a_ instead of a pronoun, or name the role (_admin, reviewer, customer_). Singular _they_ is fine when nothing else works. Never _he/she_ or _s/he._

| Before | After |
| --- | --- |
| If the user has the right permissions, he can reset other users' passwords. | If you have the right permissions, you can reset other people's passwords. |
| A reviewer sees his own tasks on the home screen. | Reviewers see their own tasks on the home screen. |

Use the pronouns a real person uses. Gendered pronouns are correct for a named person who uses them and in direct quotations.

## Gender-neutral words

| Write | Instead of |
| --- | --- |
| **chair, moderator** | chairman |
| **staff, workforce** | manpower |
| **sales representative** | salesman |
| **staffed** | manned |
| **people, humanity** | mankind |
| **artificial, synthetic** | man-made |

## Terms carrying bias

| Write | Instead of |
| --- | --- |
| **primary, secondary** | master, slave |
| **main** (branch) | master (branch) |
| **blocklist, allowlist** | blacklist, whitelist |
| **legacy, exempt** | grandfathered |
| **quick check, confidence check** | sanity check |
| **placeholder, sample** | dummy |
| **stop responding** | hang |

## Combat and violence metaphors

| Write | Instead of |
| --- | --- |
| **address, prevent, respond to** | combat, fight, eliminate |
| **threat actor** | adversary |
| **impact, scope** | blast radius |
| **attack sequence** | kill chain |
| **customer-facing** | frontline |
| **delete, reset** | nuke |
| **incident room** | war room |
| **reliable** | bulletproof |

Also avoid _strike_ and _troops._ A technical term such as the `kill` command stays as written.

## Disability

Focus on people, not conditions. _People who are blind or have low vision,_ not _the blind._ _Uses a wheelchair,_ not _wheelchair-bound._ Not _stricken with_ or _suffering from._ Don't mention a disability unless it matters to the point.

Don't use a disability as a metaphor: _crippled_ becomes _stopped_ or _slowed,_ _blind to_ becomes _unaware of._ If the replacement would change the meaning, flag it.

## Race and ethnicity

Capitalize the names of racial and ethnic groups (Asian, Black, Hispanic, Indigenous, Latino, Native American, Pacific Islander). Lowercase _white_ and _multiracial._ Keep the term the source uses for a group. If it looks outdated, flag it.

## Age

Don't use age as shorthand for skill ("so easy your grandparents can use it"). Flag it with a suggestion.

## Examples and scenarios

Use names from a range of cultures and gender identities. Vary who holds which job. Don't assume a Western or affluent setting. Don't name politically disputed places. No generalizations about groups, including flattering ones. No slang, and nothing that could read as cultural appropriation (_spirit animal, tribe_ for a team).

## Products aren't people

Don't give products human characteristics. They don't think, feel, want, or decide. This matters most for AI features, where the language invites it. The model _ranks, selects, estimates, predicts,_ and _recommends._ It doesn't _understand, believe,_ or _know._ Where the source says it does, flag it with the suggested verb. Don't rewrite the claim yourself.
